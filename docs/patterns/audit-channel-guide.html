Audit log theo pattern Channel

Middleware ghi nhận request và đẩy vào Channel<AuditLog>. Một worker nền đọc từ channel rồi ghi xuống PostgreSQL (schema audit). Request, response và thay đổi entity được mã hóa AES-256-GCM trước khi lưu.

Nguyên tắc: audit không bao giờ làm hỏng request. Mọi lỗi phát sinh khi audit chỉ được log lại rồi nuốt.

Luồng chạy của một request

Bấm từng bước (hoặc dùng nút Tiếp) để xem thành phần nào đang hoạt động. Mỗi request tạo đúng một dòng audit; thay đổi entity gộp vào cột Changes của dòng đó.

Mã hóa AES-256-GCM

Ba cột RequestBody, ResponseBody, Changes được mã hóa trước khi lưu. Khóa là base64 của đúng 32 byte, nằm ở AuditEncryption:Key.

Định dạng chuỗi lưu trong DB

v1:phiên bản
nonce12 byte ngẫu nhiên
tag16 byte xác thực
ciphertextđộ dài = plaintext

Phần sau v1: được mã hóa base64. Tiền tố phiên bản chừa chỗ cho việc xoay khóa. Nếu ai sửa dữ liệu trong DB, tag không khớp và Decrypt ném CryptographicException.

Thử ngay trong trình duyệt

Dùng WebCrypto, cùng bố cục byte với code thật. Khóa được tạo ngẫu nhiên trong trang này và không gửi đi đâu.

Worker: batch, retry, tách từng bản ghi

Một bản ghi "độc" (ví dụ chứa dữ liệu Postgres từ chối) chỉ được làm mất chính nó, không kéo theo cả batch. Thử mô phỏng bên dưới với batch 5 bản ghi, trong đó có một bản ghi lỗi.

Bấm "Chạy mô phỏng".
// Lưu cả batch trước, thất bại thì tách từng cái
if (await TrySaveWithRetryAsync(batch)) return;
if (batch.Count == 1) { /* log lỗi, bỏ */ return; }
foreach (var log in batch)
    if (!await TrySaveWithRetryAsync([log])) { /* bỏ riêng cái này */ }
Khi tắt app: StopAsync gọi Complete() rồi chờ worker drain hết hàng đợi, nên log còn lại vẫn được ghi. Channel đầy hoặc crash đột ngột thì mất log chưa ghi.

Chọn một tình huống để xem AuditType, StatusCode và ErrorMessage được quyết định thế nào.

Lưu ý và giới hạn đã biết

Bảo mật

  • 2 API đọc chưa yêu cầu đăng nhập. Cần [Authorize] trước khi dùng ngoài dev.
  • ErrorMessage, Username, Path là plaintext, có thể phản chiếu dữ liệu người dùng nhập.
  • Body đăng nhập/đăng ký lưu nguyên văn trước khi mã hóa, nên mật khẩu nằm trong dữ liệu sau khi giải mã.
  • Khóa dev nằm trong appsettings.Development.json; môi trường thật dùng secret store.

Độ tin cậy

  • Channel đầy hoặc crash đột ngột thì mất log chưa ghi.
  • Retry sau khi mất xác nhận commit có thể dính trùng khóa chính.
  • Changes vẫn được ghi nếu transaction ngoài rollback sau SaveChanges.
  • Client ngắt kết nối có thể bị ghi là Exception 500.

Dung lượng và API

  • Chưa có chính sách xóa log cũ; bảng sẽ lớn dần.
  • Request chunked lớn hơn MaxBodyBytes vẫn phải đọc hết để đếm kích thước.
  • page cực lớn có thể tràn int gây 500.
  • Thứ tự list chưa ổn định khi trùng CreatedAt.
